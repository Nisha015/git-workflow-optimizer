DevOps Implementation

Git Flow        main ──●───────────────●──── (releases only)
                develop ─●──●──●──●──●──●──●─
                feature/*  ╰─●─●─╯  release/* hotfix/*

GitHub Flow     main ──●──●──●──●──●──●──●── (always deployable)
                feature/*  ╰─●─╯ ╰─●─╯  (PR + review)

Trunk-Based     trunk ─●●●●●●●●●●●●●●●●●●●●●  (commit/merge daily)
                short branches < 1 day, feature flags

git init
git add . && git commit -m "Initial commit"
git switch -c feature/add-metrics-validation
git add . && git commit -m "feat: validate metric ranges"
git push -u origin feature/add-metrics-validation   # then open a Pull Request
git switch main && git merge feature/add-metrics-validation
# conflict demo: see scripts/demo_merge_conflict.sh

File: .github/workflows/ci.yml. On every push and pull request:

  1. Checkout code → set up Python (3.10, 3.11, 3.12 matrix)
  2. Install dependencies from requirements.txt
  3. Run pytest (API, database, scoring and frontend tests)
  4. Smoke test: start the Flask server and call /api/health

  1. Min-max normalise every metric to 0-100 (100 = best; "lower is better" metrics are inverted).
  2. Multiply by the weight: Integration Time 25%, Merge Conflicts 20%, Collaboration 20%, Deployment Failures 20%, Commit Frequency 15%.
  3. Add the five weighted values → overall score out of 100. Highest score is recommended.
Integration time has the highest default weight because it directly reflects delivery speed, the core goal of CI/CD.
